# Plan: run_audio_scribe.sh リファクタリング

## Goal

`run_audio_scribe.sh` を引数駆動・再開可能・標準準拠のメンテナンスしやすいスクリプトに作り直す。
固定パスのハードコードを排し、入力動画を引数で受け取り、途中結果をチェックポイントとして
動画と同じ階層に残すことで、失敗時や再実行時に未完了ステップだけを処理できるようにする。

## Scope

- `run_audio_scribe.sh` の全面書き換え (1 ファイルに集約)。
- ollama 用プロンプト 2 つを `prompts/` 配下の Markdown に切り出し。
- bash コーディング標準 (`standards-code` bash) への準拠。
- 引数処理・チェックポイントによるスキップ・中間ファイルのクリーンアップ。
- `lefthook.yml` への `shellcheck` / `shfmt` (Bash 用 pre-commit) 追加。

## Non-goals

- whisperx / ollama / ffmpeg のモデルやパラメータの変更 (`large-v3-turbo`, `gemma4:e4b-it-qat`,
  16kHz mono などは現状維持)。
- `docs/reports/2026-05-31-directory-structure.md` の `meet-digest` 構想 (`config/`, `src/*.py`,
  launchd) の実装。今回は単一 Bash スクリプトのまま改善する。
- 自動テストフレームワーク (bats 等) の本格導入。`shellcheck` による静的検査を主ゲートとする
  (bats は将来案として Risks に記載)。

## Background / Decisions

### 現状 (run_audio_scribe.sh)

- 入力 `./data/raw/target.mov`、出力先すべて `./data/interim/` に固定ハードコード。
- ffmpeg → whisperx → ollama(校正) → ollama(要約) を直列実行。エラー処理・再開・関数化なし。
- `HF_TOKEN="dummy"` をソースに直書き (実運用で要差し替え)。
- プロンプトはヒアドキュメントとして jq に埋め込み。要約プロンプトには `{{INPUT}}` と
  `" + . + "` の二重埋め込みが残るバグがある (`run_audio_scribe.sh:125` と `:130`)。

### 設計判断

1. **入力は引数 1 つ (動画/音声パス)**。`base` = 拡張子を除いたファイル名、`video_dir` = 入力の
   親ディレクトリ。これらから全ファイル名を導出する。
2. **作業領域は `data/interim/`、永続チェックポイントは `video_dir` (動画と同階層)**。
   - 重い処理 (whisperx, ollama) の成果物を動画と同階層にコピーして残す。
   - `data/interim/` は最終完了後に当該 `base` の中間物を削除する (使い捨て領域)。
   - したがって**再開判定は「動画と同階層のチェックポイント有無」で行う** (interim は消えるため)。
3. **要約の最終成果物は Markdown (`.md`)**。要約プロンプトの出力は `# 概要` 等の Markdown 構造の
   ため、`.srt` ではなく `.md` が自然。校正済み書き起こしは SRT 形式のまま `.srt`。
4. **プロンプトは外部 Markdown 化し、`{{INPUT}}` プレースホルダを `jq` の文字列置換で差し込む**。
   `gsub` (正規表現) ではなく `split("{{INPUT}}") | join($input)` でリテラル置換し、
   特殊文字エスケープを不要にする。
5. **`HF_TOKEN` は環境変数から取得 (決定)**。未設定なら警告のうえ `dummy` でフォールバックし、
   話者分離は失敗しうる旨を stderr に出す。`MODEL` / `API_URL` も環境変数で上書き可能・既定値あり。
6. **`standards-code` bash 準拠**: `SCRIPT_NAME`/`log_info`/`log_err`/`err`/`trap ERR`、`usage`、
   `main` での引数パース、関数は引数で値を受け取り引数数を検証、診断は stderr、一時ファイルは
   `mktemp`、冒頭に必要ツール (bash, ffmpeg, uv, jq, curl, ollama) を明記。
7. **readonly の徹底 (レビュー反映)**: 再代入しないグローバル定数・導出値・一度だけ代入する
   ローカル変数に `readonly` を付ける。既存 `API_URL` (`run_audio_scribe.sh:19`) の `readonly`
   漏れも修正する。
8. **多段パイプを避け 1 ステップ 1 中間ファイル (レビュー反映)**: ollama 処理は
   `prompt → request_json → response → .response 抽出 → 出力` を各段に分割し、段ごとに失敗検知する。
9. **大きな内容はファイル渡し (ARG_MAX 回避・レビュー反映)**: プロンプトや書き起こし全文を `--arg`
   で引数展開すると `execve` の引数長上限 (macOS 約 1MB / Linux 単一引数 128KB) に抵触しうるため、
   jq は `--rawfile`、curl は `--data-binary @file` を使い、中間は `mktemp` ファイルで受け渡す
   (Contracts の `run_ollama` 参照)。

### ファイル名規約

入力 `path/to/meeting.mov` (`base=meeting`, `video_dir=path/to`) の場合:

命名は `-` 接続のサフィックス (決定)。

| 役割                  | 作業領域 (`data/interim/`)    | チェックポイント (`video_dir`)      |
| --------------------- | ----------------------------- | ----------------------------------- |
| 音声抽出 (ffmpeg)     | `meeting.wav`                 | コピーしない (バイナリ・再生成容易) |
| 書き起こし (whisperx) | `meeting.srt` (whisperx 既定) | `meeting-asr.srt`                   |
| 校正 (ollama)         | `meeting-proofread.srt`       | `meeting-proofread.srt`             |
| 要約 (ollama, 最終)   | `meeting-summary.md`          | `meeting-summary.md`                |

### 再開・スキップのロジック

```text
0. video_dir/<base>-summary.md が存在 → 最終結果あり。何もせず終了 (要件8)。
1. ffmpeg: whisperx を実行する必要がある場合のみ interim/<base>.wav を生成。
2. whisperx: video_dir/<base>-asr.srt があれば interim/<base>.srt へコピーしてスキップ (要件6)。
            なければ実行 → interim/<base>.srt → video_dir/<base>-asr.srt へコピー (要件5)。
3. 校正:   video_dir/<base>-proofread.srt があればコピーしてスキップ。
            なければ実行 → interim/<base>-proofread.srt → video_dir へコピー。
4. 要約:   実行 → interim/<base>-summary.md → video_dir/<base>-summary.md へコピー (要件7)。
5. クリーンアップ: 全完了後に interim の <base>* を削除 (要件9)。エラー時は残す (調査用)。
```

このロジックにより、要件 6/8 の「成果物があればスキップ/何もしない」が一貫して満たされる。
クリーンアップは正常終了の最終ステップとし、`trap ERR` には含めない。

### プロンプト差し込みインターフェース

- `prompts/proofread.md` / `prompts/summarize.md` は本文中に `{{INPUT}}` を 1 箇所含む。
- スクリプトは `jq -Rs --rawfile template <prompt.md> --arg model "$MODEL"` で読み込み、
  `prompt: ($template | split("{{INPUT}}") | join($input))` として JSON を生成する。

#### 設計方針 (レビュー反映)

- **readonly の徹底**: 再代入しない設定値・導出値はすべて `readonly` を付ける。スクリプト先頭の
  グローバル定数 (`API_URL` など。現状 `run_audio_scribe.sh:19` の `API_URL` は `readonly` 漏れ) と、
  関数内で一度しか代入しないローカル変数 (`local x; x=...; readonly x`) の双方に適用する。
- **大きな内容は変数ではなくファイルで受け渡す (ARG_MAX 回避)**: プロンプトや書き起こし全文を
  `--arg` でコマンドライン引数に展開すると `execve` の引数長上限に抵触しうる
  (macOS の `ARG_MAX` は約 1MB、Linux は単一引数 128KB 上限。長時間会議の SRT は数百 KB に達しうる)。
  そのため `prompt → request json → response → .response 抽出 → 出力` の各段を**中間ファイル経由**に
  し、jq へは `--rawfile`、curl へは `--data-binary @file` で渡す。これにより引数長に依存しない。
  (`printf '%s' "$var"` 系はビルトインで `execve` を経由しないが、安全側に倒し全面ファイル渡しに統一。)
- **1 ステップ 1 変数 (ファイル) で段階分け**: 多段パイプをやめ、各段を独立した行・中間ファイルに
  分割して段ごとに失敗検知する。
- **中間ファイルは `mktemp` + `EXIT` トラップで掃除**: 作業用の一時ファイルは `mktemp` で作成し、
  グローバル配列に登録して `trap 'rm -f ...' EXIT` で一括削除する (standards-code: 一時ファイルは
  `mktemp`)。これは要件9の `data/interim/<base>*` 削除とは別系統 (こちらは純粋な一時物)。

```bash
function run_ollama() {
  # args: <prompt_template_file> <input_file> <output_file>
  [[ $# -eq 3 ]] || err "${LINENO}" "run_ollama requires 3 args"
  local template_file="$1" input_file="$2" output_file="$3"

  # 作業用の一時ファイル (mktemp; EXIT トラップで掃除する想定。register_tmp は補助関数)
  local prompt_file request_file response_file
  prompt_file=$(mktemp) && register_tmp "$prompt_file"
  request_file=$(mktemp) && register_tmp "$request_file"
  response_file=$(mktemp) && register_tmp "$response_file"
  readonly prompt_file request_file response_file

  # 1. プロンプト生成: template の {{INPUT}} を入力で置換 → prompt_file
  #    入力はすべてファイル (--rawfile template, 位置引数 input_file)。引数長に依存しない。
  jq -Rs --rawfile template "$template_file" \
    '. as $input | $template | split("{{INPUT}}") | join($input)' \
    "$input_file" >"$prompt_file"

  # 2. request json 生成: prompt をファイルから読む (--rawfile) → request_file
  jq -n --arg model "$MODEL" --rawfile prompt "$prompt_file" \
    '{ model: $model, stream: false, options: { temperature: 0 }, prompt: $prompt }' \
    >"$request_file"

  # 3. ollama 呼び出し: リクエストボディはファイル参照 (--data-binary @file) → response_file
  curl -sS "$API_URL" -H "Content-Type: application/json" \
    --data-binary @"$request_file" >"$response_file"

  # 4. .response 抽出 (null/空なら -e で非ゼロ → エラー) → output_file
  jq -e -r '.response' "$response_file" >"$output_file" \
    || err "${LINENO}" "ollama returned no .response (model=$MODEL)"
}
```

## Verification Strategy

実行スタイル: **Staged** (挙動ロジックよりインフラ/構成の機械的整理が主)。各ステージに静的検査と
スモーク確認を紐付ける。

- `shellcheck run_audio_scribe.sh` がクリーン (主ゲート)。
- `shfmt -d run_audio_scribe.sh` で整形差分なし (lefthook 連携は Risks 参照)。
- プロンプト Markdown: `pnpm cspell lint --no-progress prompts/*.md`、
  `npx prettier --check 'prompts/*.md'`。新語は `.cspell.json` に追加。
- ロジック確認 (外部コマンドに依存しない単体検証):
  - `--help` が usage を表示し exit 0。
  - 引数なし/存在しないファイルで stderr エラー + 非ゼロ終了。
  - jq のプロンプト組み立てを、ダミー template/input で実行し `{{INPUT}}` が置換されること
    (`jq` 単体で確認、ollama 呼び出しなし)。
  - 既存 `video_dir/<base>-summary.md` を置いた状態で「何もせず終了」する分岐。
- フルパイプラインのスモーク確認は ffmpeg/whisperx/ollama/HF トークンが必要なため、環境が整った
  ユーザー側での手動実行に委ねる (計画では実コマンド実行はしない)。

> 注: 本セッションは context-mode 上で実行しており、`curl` は MCP 側でブロックされる。スクリプト
> 内の `curl` 記述は問題ないが、検証時にエージェントが `curl` を直接実行しないこと。
